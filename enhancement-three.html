Enhancement Three: Databases

Enhancement Overview

For this enhancement, I improved the SQLite database used by the weight-tracking application. The database stores user accounts, goals, and weight entries, so the changes focus on security, reliability, organization, and more efficient access to user data.

Original Artifact

The original database already used separate users, goals, and weight_entries tables, primary keys, unique email addresses, ContentValues, and parameterized selection arguments. However, password storage, relationship enforcement, record ownership, date ordering, and database efficiency could be improved.

Enhancements Completed

  • Strengthened the relationship between users, goals, and weight entries using foreign-key concepts.
  • Improved password protection instead of relying on plain-text password storage.
  • Used parameterized queries and user-specific conditions for safer record access.
  • Restricted update and delete operations using both the user ID and record ID.
  • Standardized dates and improved sorting by entry date.
  • Added validation and improved exception handling around database operations.
  • Planned indexing on user ID and entry date to improve common searches and sorting.
  • Improved database design for record editing, date searching, and more efficient retrieval.
  • Considered database migrations instead of destructive upgrades.

Course Outcome Connection

This enhancement demonstrates database design and security practices through SQLite, relational relationships, CRUD operations, indexing, parameterized queries, and user-specific data access. It also demonstrates a security mindset by protecting stored credentials and limiting access to records that belong to the logged-in user.

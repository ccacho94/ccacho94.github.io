Enhancement Three: Databases

Enhancement Overview

I selected my weight-loss tracking application, which I originally created for my CS-360 Mobile Architecture and Programming course at the beginning of 2026. The Android application allows users to create an account, log their weight, set a target weight, review previous entries, and receive a notification when they reach their goal.

I chose this artifact because I would eventually like to publish the application on the Google Play Store. Improving the database makes the application more practical for multiple users and gives me experience working with data storage, security, and account-based information.

Original Artifact

The original application used SQLite to store user accounts and weight entries. It already provided the basic functionality needed to save user information, record weights, and display previous entries. However, the database needed stronger security controls, more efficient searches, and better protection between different user accounts.

The original database also required improvements to password storage, record ownership, date searching, and database relationships before the application could better support multiple users.

Enhancements Completed

  • Used SQLite tables and relationships to organize user accounts and weight entries.
  • Linked each weight entry to the correct account using a user ID as a foreign key.
  • Filtered database results by the logged-in user ID so users can only access their own weight records.
  • Added searchable weight history by allowing users to search for a specific date or an inclusive date range.
  • Added the ability to update and delete existing weight entries.
  • Added indexes on the user ID and date fields to improve search and sorting efficiency.
  • Added foreign-key cascade rules so deleting a user account also removes related weight entries.
  • Required both the entry ID and logged-in user ID when updating or deleting database records.
  • Used parameterized queries to reduce the risk of SQL injection.
  • Replaced plain-text passwords with salted password hashes.
  • Improved database versioning and schema updates while considering how to preserve existing user records.

Skills Demonstrated

This enhancement showcases my database development skills through the use of SQLite tables, relationships, queries, indexes, and security controls. Each weight entry contains a user ID that connects the record to the correct account. When a user logs in, the application retrieves only records associated with that user ID.

This demonstrates my ability to work with relational database concepts, primary and foreign keys, CRUD operations, date-range searches, indexes, parameterized queries, account-based filtering, cascade deletion, password hashing, and database version upgrades.

Database Security and Performance

The database was improved by adding indexes on the user ID and date fields. These indexes help SQLite locate user-specific records and date ranges more efficiently.

Database updates and deletions require both the entry ID and the logged-in user ID. This adds another layer of protection by making sure a record belongs to the correct account before it can be changed or removed.

Parameterized queries are used instead of directly combining user input with SQL commands. This reduces the risk of SQL injection because user input is treated as data rather than executable SQL.

Password storage was also improved by replacing plain-text passwords with salted password hashes. This protects account credentials more effectively if stored data is exposed.

Course Outcome Connection

I met the course outcome I planned to support with this enhancement. The main outcome was developing a security mindset that anticipates potential software vulnerabilities, protects user privacy, and improves the security of data and resources.

Separating records by user account, using parameterized queries, protecting passwords, and limiting database changes to the correct user demonstrate this outcome. These changes reduce the possibility of unauthorized access to another user's information and improve the overall security of the application.

The enhancement also strengthened my ability to design and evaluate computing solutions because I had to consider database structure, query performance, relationships between data, and the trade-offs involved in modifying an existing database.

My outcome-coverage plan has not changed because this database enhancement provided strong support for the security outcome I planned to address.

Challenges and Lessons Learned

While completing this enhancement, I learned more about relational database design and the importance of connecting records through primary and foreign keys. I also learned that database security involves more than protecting the database file. Each query must be designed so users can access only their own information.

One challenge I faced was modifying the existing database without breaking the application's other features. I had to make sure the DatabaseHelper, repositories, ViewModel, and activity all used matching method parameters.

Another challenge was handling dates. The application displays dates using the MM/DD/YYYY format, but it stores a second date value using the YYYY-MM-DD format so SQLite can correctly sort and search date values.

I also had to decide how to update the existing database schema while preserving older user records. Working through these challenges improved my ability to review existing code, plan database changes, troubleshoot connections between application layers, and create a more secure and useful application.

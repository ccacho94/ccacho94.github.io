Enhancement Two: Algorithms & Data Structures

Enhancement Overview

I enhanced my weight-loss tracking application, which I originally created for my CS-360 Mobile Architecture and Programming course at the beginning of 2026. The Android application allows users to create an account, log their weight, set a target weight, view previous entries, and receive a notification when they reach their goal.

I selected this artifact for my ePortfolio because I plan to publish it on the Google Play Store. Feedback from real users could help me continue improving the application while giving me more real-world software development experience.

Original Artifact

The original application stored weight records and allowed users to view their history and determine whether they had reached a target weight. However, it did not analyze the user’s weight over time or provide feedback about whether their weight was increasing, decreasing, or staying the same.

The original application also needed a better way to organize entries by date. Sorting records chronologically is important because the application must compare the correct two most recent entries when calculating a weight trend.

Enhancements Completed

  • Added a trend-tracking feature that compares a user’s weight entries over time.
  • Retrieved stored weight records from the database and placed them into a list for sorting and analysis.
  • Sorted weight entries chronologically using MergeSort.
  • Used MergeSort with a runtime of O(n log n) to ensure that the two most recent records are identified in the correct order.
  • Used a HashMap with the user ID as the key to organize records and provide an average lookup time of O(1).
  • Compared the newest weight entry with the previous entry to determine whether the user's weight is increasing, decreasing, or staying the same.
  • Added date validation to help ensure that weight entries are processed in the correct chronological order.
  • Connected the database, repository, ViewModel, and activity so the trend information updates when an entry is added or deleted.

Skills Demonstrated

This enhancement showcases my skills in algorithms and data structures through the way weight records are stored, organized, sorted, and analyzed. Each record contains the user ID, date, and weight value, allowing the application to process the information and provide meaningful feedback to the user.

The enhancement demonstrates my ability to work with lists, HashMaps, sorting algorithms, comparison logic, conditional statements, date validation, and runtime analysis. Instead of only displaying stored weight information, the application now analyzes the data and helps users better understand their progress.

Algorithm Analysis

The weight entries are sorted chronologically using MergeSort. MergeSort has a runtime of O(n log n), which provides consistent performance as the number of weight records increases.

After the records are sorted, the application compares the two newest entries. If the newest weight is higher, the application reports that the user's weight is increasing. If it is lower, the weight is decreasing. If both values are equal, the application reports that the weight is staying the same.

A HashMap is also used to organize records using the user ID as the key. This provides an average lookup time of O(1) when locating information associated with a specific user.

Challenges and Lessons Learned

While enhancing the application, I learned how algorithms and data structures can turn stored data into useful feedback for the user. I gained more experience working with lists, HashMaps, MergeSort, runtime analysis, date validation, and comparison logic.

One of the main challenges I faced was deciding whether to create a separate class for the MergeSort algorithm or incorporate the sorting logic into an existing class. A separate class would make the algorithm easier to test and reuse, while adding it to the existing ViewModel would reduce the number of files and keep the enhancement connected to the current application structure.

I decided to place the sorting logic inside the existing ViewModel while keeping the HashMap inside the repository. This decision helped me better understand the trade-offs between separation of responsibilities, code organization, reusability, and simplicity.

I also had to make sure that the database, repository, ViewModel, and activity worked together correctly so the trend would update whenever a weight entry was added or deleted.
